## 1. PURPOSE

This document defines the complete database schema, table relationships, Row Level Security policies, and API patterns for RepFlow. Every database change must be made through migration files and must align with what is written here.

This document does NOT cover:
- Visual design (see UIUX.md)
- Product features (see PRD.md)
- Technical stack decisions (see TRD.md)
- Phase by phase tasks (see IMPLEMENTATION.md)

---

## 2. DATABASE OVERVIEW

- Provider: Supabase (PostgreSQL)
- All tables live in the `public` schema
- All changes made via migration files in `/supabase/migrations/`
- RLS enabled on every table — no exceptions
- All primary keys are UUID generated by `gen_random_uuid()`
- All timestamps use `timestamptz` with `default now()`

---

## 3. ENTITY RELATIONSHIP OVERVIEW

```
auth.users (Supabase managed)
    │
    ├── users_profile (1:1)
    ├── user_preferences (1:1)
    ├── workout_plans (1:many)
    ├── workout_sessions (1:many)
    ├── exercise_favorites (1:many)
    ├── user_streaks (1:1)

categories (1:many) ──── exercises (many:1) ──── equipment (many:1)
                              │
                    ┌─────────┼──────────┐
                    │         │          │
              session_   exercise_   social_
              exercises  favorites   posts
```

### 4.1 `users_profile`

Stores the public profile information for each user.

```sql
create table users_profile (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid references auth.users unique not null,
  name        text,
  avatar_url  text,
  created_at  timestamptz default now()
);
```

| Column | Type | Notes |
|---|---|---|
| id | uuid | Primary key |
| user_id | uuid | FK to auth.users — unique (one profile per user) |
| name | text | Display name from onboarding |
| avatar_url | text | URL to Supabase Storage user-avatars bucket |
| created_at | timestamptz | Auto-set on insert |

**RLS Policies:**
```sql
alter table users_profile enable row level security;

create policy "Users can read own profile"
on users_profile for select
using (auth.uid() = user_id);

create policy "Users can insert own profile"
on users_profile for insert
with check (auth.uid() = user_id);

create policy "Users can update own profile"
on users_profile for update
using (auth.uid() = user_id);
```

### 4.5 `exercises`

Core content table. Every exercise in the library.

```sql
create table exercises (
  id                uuid primary key default gen_random_uuid(),
  name              text not null,
  slug              text not null unique,
  category_id       uuid references categories,
  equipment_id      uuid references equipment,
  difficulty        text not null,
  primary_muscles   text[] not null,
  secondary_muscles text[],
  sets              integer,
  reps              text,
  rest_time         text,
  instructions      text,
  tips              text,
  common_mistakes   text,
  video_url         text,
  video_url_side    text,
  video_url_front   text,
  image_url         text,
  is_published      boolean default false,
  created_at        timestamptz default now(),
  updated_at        timestamptz default now()
);
```

| Column | Type | Values / Notes |
|---|---|---|
| slug | text | URL-safe unique identifier e.g. "push-up" |
| difficulty | text | beginner / intermediate / advanced |
| primary_muscles | text[] | e.g. ['Chest', 'Shoulders'] |
| secondary_muscles | text[] | e.g. ['Triceps', 'Core'] |
| sets | integer | e.g. 3 |
| reps | text | text to allow ranges e.g. "12–15" or "60s" |
| rest_time | text | e.g. "60s" or "90s" |
| instructions | text | Full step-by-step text |
| tips | text | Form tips text |
| common_mistakes | text | Common mistakes text |
| video_url | text | Primary video URL (Supabase Storage or R2) |
| video_url_side | text | Side angle video URL |
| video_url_front | text | Front angle video URL |
| image_url | text | Fallback image URL |
| is_published | boolean | false = hidden, true = visible to all users |

**Image/Video Fallback Logic (in code):**
```typescript
// Priority order in every exercise page:
// 1. video_url → show <video> element
// 2. image_url → show <img> element
// 3. /public/exercises/{slug}.jpg → show local image
// 4. placeholder → show grey box
```

**RLS Policies:**
```sql
alter table exercises enable row level security;

create policy "Anyone can read published exercises"
on exercises for select
using (is_published = true);
```

**Indexes:**
```sql
create index exercises_slug_idx on exercises(slug);
create index exercises_category_id_idx on exercises(category_id);
create index exercises_equipment_id_idx on exercises(equipment_id);
create index exercises_is_published_idx on exercises(is_published);
```

### 5.1 `user_streaks` (Phase 6)

Tracks daily workout consistency per user.

```sql
create table user_streaks (
  id                uuid primary key default gen_random_uuid(),
  user_id           uuid references auth.users unique not null,
  current_streak    integer default 0,
  longest_streak    integer default 0,
  last_workout_date date,
  total_workouts    integer default 0,
  created_at        timestamptz default now(),
  updated_at        timestamptz default now()
);
```

**Streak Logic (server side):**
- On workout completion → check `last_workout_date`
- If yesterday → increment `current_streak`
- If today already → no change (one workout per day)
- If more than 1 day ago → reset `current_streak` to 1
- Update `longest_streak` if `current_streak` exceeds it
- Always increment `total_workouts`

**RLS Policies:**
```sql
alter table user_streaks enable row level security;

create policy "Users can read own streak"
on user_streaks for select
using (auth.uid() = user_id);

create policy "Users can insert own streak"
on user_streaks for insert
with check (auth.uid() = user_id);

create policy "Users can update own streak"
on user_streaks for update
using (auth.uid() = user_id);
```

### 5.4 `session_exercises` (Phase 6)

Records each exercise performed within a workout session.

```sql
create table session_exercises (
  id          uuid primary key default gen_random_uuid(),
  session_id  uuid references workout_sessions not null,
  exercise_id uuid references exercises not null,
  order_index integer not null,
  sets_done   integer default 0,
  reps_done   text,
  weight      text,
  notes       text,
  created_at  timestamptz default now()
);
```

| Column | Type | Notes |
|---|---|---|
| order_index | integer | Position in the workout (1, 2, 3...) |
| reps_done | text | Text to allow ranges — e.g. "12" or "10–12" |
| weight | text | Text to allow units — e.g. "20kg" or "bodyweight" |

**RLS Policies:**
```sql
alter table session_exercises enable row level security;

create policy "Users can manage own session exercises"
on session_exercises for all
using (
  auth.uid() = (
    select user_id from workout_sessions
    where id = session_exercises.session_id
  )
);
```

## 6. STORAGE BUCKETS

| Bucket | Access | Contents | Naming Convention |
|---|---|---|---|
| `exercise-videos` | Public read | MP4 exercise demos | `{slug}.mp4`, `{slug}-side.mp4`, `{slug}-front.mp4` |
| `exercise-images` | Public read | JPG/PNG exercise images | `{slug}.jpg` |
| `user-avatars` | Private (user only) | Profile pictures | `{user_id}.jpg` |

**Bucket Policies:**
```sql
-- exercise-videos: public read
create policy "Public read exercise videos"
on storage.objects for select
using (bucket_id = 'exercise-videos');

-- exercise-images: public read
create policy "Public read exercise images"
on storage.objects for select
using (bucket_id = 'exercise-images');

-- user-avatars: private
create policy "Users can manage own avatar"
on storage.objects for all
using (
  bucket_id = 'user-avatars'
  and auth.uid()::text = (storage.foldername(name))[1]
);
```

## 8. COMMON QUERY PATTERNS

### Get current user's preferences
```typescript
const { data } = await supabase
  .from('user_preferences')
  .select('*')
  .eq('user_id', user.id)
  .single()
```

### Get published exercises with relations
```typescript
const { data } = await supabase
  .from('exercises')
  .select(`
    *,
    category:categories(id, name, slug),
    equipment:equipment(id, name, slug)
  `)
  .eq('is_published', true)
  .order('name')
```

### Get exercise by slug
```typescript
const { data } = await supabase
  .from('exercises')
  .select(`
    *,
    category:categories(id, name, slug),
    equipment:equipment(id, name, slug)
  `)
  .eq('slug', slug)
  .eq('is_published', true)
  .single()
```

### Filter exercises by equipment slug
```typescript
const { data } = await supabase
  .from('exercises')
  .select(`*, equipment:equipment(id, name, slug)`)
  .eq('is_published', true)
  .eq('equipment.slug', equipmentSlug)
```

### Get user streak
```typescript
const { data } = await supabase
  .from('user_streaks')
  .select('*')
  .eq('user_id', user.id)
  .single()
```

### Save exercise as favorite
```typescript
const { error } = await supabase
  .from('exercise_favorites')
  .insert({ user_id: user.id, exercise_id: exerciseId })
```

### Remove exercise from favorites
```typescript
const { error } = await supabase
  .from('exercise_favorites')
  .delete()
  .eq('user_id', user.id)
  .eq('exercise_id', exerciseId)
```

## 10. RULES

- Never modify database structure through the Supabase dashboard directly
- Every schema change goes in a new numbered migration file
- Every new table must have RLS enabled and policies defined
- Never use `select *` in production code — always specify columns
- Never expose service role key in client code
- Always use parameterized queries via Supabase client — never raw SQL in app code
- Always handle the `error` return from every Supabase call
- Indexes must be added for any column used in `where` or `order by` clauses frequently
